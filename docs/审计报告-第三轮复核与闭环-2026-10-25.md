## 2. 明确接受/延后的项

| 项 | 原因 |
|---|---|
| Mail `reload_if_changed` 约 49µs/次 | 文件 metadata 的固有成本；已在 API 文档写明“按秒/文件监听调用，勿放每封邮件路径” |
| Mail `parse_mailbox` 简化解析 | 当前覆盖 `"昵称 <a@b.com>"` 等常用格式；改用 lettre 解析器会改变接受范围，收益低 |
| Mail SMTP 连接复用 | 与 C# 每次 `using var client` 一致；仅高吞吐场景有收益，作为独立改造 |
| SMS `template_params_json` 约 1µs | 量级极小，保持简单 |
| SMS `settings()` 克隆约 2.6µs/10 账号 | 相对网络耗时可忽略；改 Arc 快照会扩大配置 API |
| SMS `http` body 每次重试克隆 | 保留简单接口；大请求体可自行包 `Arc`，收益有限 |
| SMS 客户端缓存 | 需处理配置热更新失效，复杂度高于收益 |
| SMS `send_with_code` 不检查 `IsEnabled` | 与 C# `FindByCode` 一致，已在文档写明 |
| DH `secret::SecretString` | 当前手写 Debug + 测试已防泄露；类型化迁移是破坏性 API 变更 |
| DH `errors::AttemptFailure` | Mail/SMS 字段语义不同，抽象收益低 |
| HTTP 持久化客户端/连接池 | 需要后台运行时与连接复用设计，属于独立架构改造 |
| Mail SMTP 连接池 | 同上；当前低频发送无收益 |
