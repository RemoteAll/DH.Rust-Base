# 网络层选型复核（成熟 Rust 库准入：两条件实证）

> 背景：DHDeploy.Agent → Rust 迁移的网络内核（HTTP / WebSocket）选型复核。
> **准入闸门（用户设定）**：① 与自研对比，成熟库性能不劣（总原则：**性能必须更优**）；
> ② 成熟库可按我们需求调整代码。**两条同时满足才允许采用成熟库。** 本文以实测 + 源码取证裁决。

## 1. 条件①：性能实测（Windows 11 回环，2026-09-28 复测）

方式：同一自研压测器施加相同负载；64 并发 × 2000 请求/消息 × 4 进程（WS 4KB 档为 32×1000×2）；
TCP nodelay；机器整体负载会带来 ±10% 波动，**以同轮内横向比较为准**。

### WebSocket（聚合 mps；回显场景）

| 场景 | ws_raw（自研极简） | ws_tungstenite | ws_fast（fastwebsockets） | 判定 |
|------|------------------:|---------------:|--------------------------:|------|
| 256B 回显 | 62,841 | 58,867 | 59,327 | 噪声区间（上次会话：fast 73,975 > raw 72,581） |
| 4KB 回显 | 48,320（max>40ms 尖刺） | 59,929 | **65,052** | **fastwebsockets 明确更优**（+8.5% vs tungstenite、+35% vs 自研） |

### HTTP（聚合 rps）

| 场景 | http_raw（自研极简） | http_hyper | http_axum | 判定 |
|------|--------------------:|-----------:|----------:|------|
| GET /ping（64×2000×4） | 64,687 | 62,381 | 57,324 | 自研玩具 +3.7% vs hyper |
| POST /echo 1KB（64×2000×4） | 56,068 | 51,425 | 53,321 | 自研玩具 +9% vs hyper（峰值 60ms 尖刺） |

### 裁决

- **WS：成熟库（fastwebsockets）确凿更优** → 条件①满足（自研做不到更好）。
- **HTTP：自研"极简玩具"微基准领先 hyper 4~9%**，但该实现无 chunked/流式上传（文件分片上传必需）、
  无完善保活/错误处理/升级/安全加固，属「性能上界参照」而非可用实现；且领先幅度处于回环噪声量级。
  **不以该 4~9% 作为推翻 hyper 的依据。**
- 为兑现「性能必须更优」总原则，批次 5 设**硬性验收基准**（razor 同款"基准先行、双端对照"模式）：
  1. dhrust HTTP/WS 完整实现 ≥ 对应裸库基准（同一 harness 复测）；
  2. 与 C# DH.NCore 等价服务同机对照：吞吐与 p99 不劣；
  3. 任一项不达标 → 触发**强化自研预案**（httparse 内核 + 自研连接循环）再对比定案。
- 自研极简版（ws_raw / http_raw）保留为参照基线与特殊窄协议备选。

## 2. 条件②：可调整性取证（源码级，取自实际依赖版本）

### fastwebsockets 0.8.1（Apache-2.0；8 文件 / 63.6KB → 可 vendor/fork）

| 我们的需求 | 可调整点（公开 API） |
|------------|---------------------|
| 自管 HTTP 升级/握手（对齐 DH.NCore 握手语义） | `after_handshake(stream, role)` / `after_handshake_split`：绕过其握手，在任意 IO 上直接接管 |
| 帧级控制（中继转发/粘包语义） | `read_frame`；`Frame` + `Payload<'a>`（借用零拷贝）；`mask()/unmask()`；`fmt_head` |
| 写路径吞吐 | `write_frame(mask)`；`writev` + `set_writev_threshold` |
| 关闭自动行为（自管心跳/关闭） | `set_auto_close` / `set_auto_pong` / `set_auto_apply_mask` / `set_max_message_size` |
| 客户端/服务端双角色 | `Role::{Server, Client}`；`split` 读写分离；`into_inner` 回取底层流 |
| 需再深改时 | 体量小（63KB），fork/vendor 成本低，供应链可控 |

### hyper 1.11.1（MIT）

| 我们的需求 | 可调整点（公开 API） |
|------------|---------------------|
| 任意 IO（如自研会话对象/统计包装） | `http1::Builder::serve_connection(io, service)`：IO 与 Service 全泛型 |
| WS 升级 | `serve_connection(...).with_upgrades()` + `hyper::upgrade::on(req)` |
| 自研语义层（Map/Use 路由、会话、鉴权） | 实现 `hyper::service::Service`，请求/响应/扩展随意包装 |
| 连接调优 | `max_buf_size`、`pipeline_flush`、`keep_alive`、`half_close` |
| Body 零拷贝透传 | `http-body` 抽象可自定义 `Body` 实现（复用我们的缓冲） |
| 需再深改时 | 体量较大、fork 成本高；但上述能力均为公开 API，**无需改库即可组合** |

## 3. 结论

- **默认组合通过两条件**：`hyper`（HTTP 语法/连接层）+ `fastwebsockets`（WS 帧层）+
  **dhrust 自研语义层**（DH.NCore 的路由 Map/Use、会话模型、心跳/Pong 超时、粘包拆包、
  掩码策略、中继转发语义全部在我们的代码内）。
- 性能红线与触发预案见 1 节裁决；若架构师要求 HTTP 也必须以自研冲刺上述 4~9%，
  则按第 1 节预案（强化自研）做对比测试后定案。
- 量级参照：razor 引擎原生路径已达 p50 13.7µs / 2.07x C#；网络层沿用同一基准验收模式。

## 4. 复现

```powershell
# WebSocket（fastwebsockets / tungstenite / 自研）
powershell -ExecutionPolicy Bypass -File tools\bench-net\run-ws.ps1   -Conns 64 -Msgs 2000 -PayloadSize 256  -Loaders 4
powershell -ExecutionPolicy Bypass -File tools\bench-net\run-ws.ps1   -Conns 32 -Msgs 1000 -PayloadSize 4096 -Loaders 2
# HTTP（hyper / axum / 自研）
powershell -ExecutionPolicy Bypass -File tools\bench-net\run-http.ps1 -Conns 64 -Reqs 2000 -Mode get -Loaders 4
powershell -ExecutionPolicy Bypass -File tools\bench-net\run-http.ps1 -Conns 64 -Reqs 2000 -Mode post -BodySize 1024 -Loaders 4
```
