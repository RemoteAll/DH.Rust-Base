# Razor 子集模板引擎需求

> 所属库：DH.RustBase（crate `dhrust`，feature `razor`）
> 路线：方案 C——Razor 子集双端引擎（C# 原生 Razor ↔ Rust 引擎，同一份 `.cshtml` 双端渲染）
> 立项：2026-09-28

## 1. 背景与目标

### 1.1 为什么做
- DH 生态 Web 页面（Cube 后台等）以 C# Razor（`.cshtml`）为主力，页面资产规模大、整体改写成本高。
- 用 Rust 重写 Web 服务（如 DHDeploy.Agent、后续 Cube 服务化）时，若无同源模板能力，页面必须改写为另一种语法，且此后 C#/Rust 文件永久分叉。
- 原生 Razor 与 C# 编译器深度耦合（模板即 C# 类、表达式即任意 C#），无法在 Rust 端原样执行；社区无成熟 Rust 实现。

### 1.2 成功标准（可衡量）
- **同源**：同一份 `.cshtml`，C# 端由原生 Razor 渲染、Rust 端由本引擎渲染，**子集内输出逐字节一致**。
- **可切换**：任一模块可在 C# 与 Rust 之间切换渲染实现，模板文件零修改。
- **性能**：同模板、同数据、warm 状态下，Rust 引擎单线程渲染吞吐 **不低于** C# 原生 Razor（同口径）；端到端（含 HTTP）不低于 C# 方案。
- **可控**：子集之外的语法在 Rust 端**显式报错**（行列号定位），杜绝静默行为不一致。

## 2. 用户角色

| 角色 | 说明 | 核心诉求 |
|------|------|---------|
| Rust 服务开发者 | 用 Rust 编写/迁移 Web 服务 | 直接复用既有 `.cshtml`，不再改写页面 |
| C# 页面维护者 | 继续用 VS/Razor 工具链维护同一批模板 | 现有工具链与页面资产不受影响 |
| 架构师 | 决定模块在 C#/Rust 间切换 | 可随时双向切换，风险可控、可回退 |

## 3. 功能需求

### 3.1 解析与求值核心
- **F001 模板解析（Must）**：扫描 HTML 文本与 Razor 代码混合内容，生成可渲染结构。
  - AC1：`@Model.X`、`@(表达式)`、`@* 注释 *@`、纯文本均可解析；
  - AC2：解析错误含行、列与原因。
- **F002 表达式子集求值（Must）**：路径访问、字面量、算术/比较/逻辑/三元/`??`。
  - AC：架构文档「3.2 子集规约 v0.1」用例全部通过。
- **F003 HTML 自动转义（Must）**：隐式表达式默认转义；`@Raw(...)`/`@Html.Raw(...)` 显式不转义。
  - AC：转义用例与 C# 端逐字节一致。
- **F004 控制流 if（Must）**：`@if (...) { } else if (...) { } else { }`（含嵌套）。
  - AC：分支用例双端一致。
- **F005 循环 foreach（Must）**：`@foreach (var x in 表达式) { }`（含嵌套）。
  - AC：列表/空列表/嵌套循环用例双端一致。
- **F006 错误报告（Must）**：子集外语法（`@using`、LINQ、`@switch` 等）给出「不支持 + 位置 + 建议」错误。
  - AC：负向用例报错信息含行列号与原因。

### 3.2 页面级能力
- **F007 代码块 `@{ ... }`（Should）**：仅允许 `var 名称 = 表达式;` 声明序列。
  - AC：声明变量可在后续表达式引用；非法语句报错。
- **F008 布局与分区（Should）**：`@{ Layout = "..." }`、`@RenderBody()`、`@section X { }`、`@await RenderSectionAsync("X", false)` 固定模式。
  - AC：两级布局用例双端一致。
- **F009 Partials（Should）**：`@await Html.PartialAsync("Name", model)` 固定模式，递归渲染。
  - AC：同页多 partial、传递子模型用例双端一致。
- **F010 模板缓存（Should）**：按文件路径 + mtime/长度变更自动失效。
  - AC：修改文件后下次渲染生效。

### 3.3 验证与集成
- **F011 双端一致性用例集与互操作脚本（Must）**：模板/数据/期望输出成对用例；C# 工具与 Rust 引擎双端渲染逐字节比对，脚本一键执行。
  - AC：脚本输出 `RAZOR INTEROP PASSED`。
- **F012 性能基准（Must）**：同模板同数据对比 Rust 引擎与 C# Razor（编译缓存同口径），输出吞吐与分位延迟。
  - AC：达成 1.2 性能目标，或给出差距分析与 F014 触发结论。
- **F013 HTTP 集成（Should）**：`dhrust::http` 提供 `View` 响应（模板路径 + 模型 → HTML）。
  - AC：示例服务返回渲染页面。
- **F014 代码生成优化（Could）**：将模板编译为 Rust 函数（Askama 级）。
  - 触发条件：F012 未达标。

## 4. 非功能需求

- **性能**：warm 渲染吞吐 ≥ C# 同口径；无第三方运行时依赖；目标小页面（≤100 节点、100 行数据）单线程 ≥ 1 万次/秒（初值，基准后固化）。
- **安全**：默认转义防 XSS；求值引擎非图灵完备、无任意代码执行；「不转义」必须显式 `Raw` 且可审计；模板来源为受控目录。
- **兼容性**：子集内模板在 ASP.NET Core Razor（.NET 10）编译通过率 100%（由 C# 互操作工程证明）；Rust 端对超集语法必须报错；不影响 dhrust 既有模块行为（默认 feature 不变）。

## 5. 边界与约束

- **明确不做（v0）**：完整 C# 表达式语言；`@using`/`@inject`/`@functions`/`@helper`；`@switch`/`@while`；异步表达式（除 F009 固定模式）；permessage-deflate。
- **已知限制**：Rust 端对模型属性为运行期校验（C# 为编译期）；数值/布尔文本化按 C# 语义实现，个别格式差异以用例集为准逐项修复。
- **回退路线**：若性能目标无法达成且优化空间耗尽，回退方案 A（Liquid/Handlebars 双端标准）或实施 F014。
