# bench-view：Razor 视图渲染性能基准（Rust 引擎 vs C# 原生 Razor）

目的：验证「Razor 子集模板引擎」（方案 C）的性能目标——小页面（≤300 节点、100 行数据）
单线程 warm 渲染吞吐不低于 C# 原生 Razor（同口径），并为 F012（性能基准）验收提供实测数据。

## 对比对象

| 侧 | 实现 | 运行方式 |
|----|------|---------|
| Rust 解释器 | `dhrust::razor`（解释器：解析一次 + 逐节点求值/写出） | `bench-view`（本目录，Release：LTO + 单代码元） |
| Rust 原生 | F014 生成代码（模板 → Rust 源码 → cdylib） | `bench-view` 传 dll 参数（`NativeTemplate::render`） |
| C# | RazorEngineCore 2026.1.1（原生 Razor 编译为委托，关闭调试信息） | `tools/csharp/RazorInterop bench`（Release，net10.0） |

两端同口径：模板解析/编译**只做一次**；计时循环内仅执行「模型绑定 + 渲染」；
warmup 默认 1000 次、计时 20000 次；每次迭代单独取时间戳并计算分位。
模型为同一 JSON（`fixtures/data.json`，100 行 × 4 字段）；模板 `fixtures/template.cshtml`
（表格循环 + 条件属性 + 成年判断，输出约 7.5KB）。

基准前先做 sanity：双端渲染同一夹具并**逐字节比对**，不一致直接失败（防止拿"渲染不同内容"比速度）。

## 测试环境

- Windows 11（本机）；rustc 1.98.1，Release（仓库根与 bench-view 均启用 `lto = true`、`codegen-units = 1`）；
- .NET 10 Release；两端均为单线程、进程内循环；
- 公平性说明：两端均使用各自发布默认设置，无 unsafe 预缓存、无跳过转义等基准技巧。

## 实测结果（2026-09-28）

### 主场景（100 行循环，20000 次迭代，2026-09-28 最终）

| 指标 | Rust 解释器 | Rust 原生（F014） | C# |
|------|-----------:|-----------------:|----:|
| 吞吐（ops/sec） | 31,326 | **69,257** | 33,440 |
| 均值（µs） | 31.81 | **14.35** | 28.92 |
| p50（µs） | 30.50 | **13.70** | 15.00 |
| p90（µs） | 31.80 | **14.10** | 92.80 |
| p99（µs） | 64.70 | **31.20** | 160.10 |

> 原生/C# 吞吐比 **2.07x**；p50 13.7µs 优于 C# 15.0µs；p99 31µs 约为 C# 的 1/5。
> C# 均值/尾延迟受 GC 波动主导（复跑吞吐比 0.83x~1.24x 摆动）；解释器与原生均无分配尖峰、数字稳定。

### 性能分解（探针模板，p50/次）

| 微型模板（均 ×100 行） | p50（µs） | 说明 |
|----------------------|----------:|------|
| `foreach` 空循环 | 2.0 | 循环框架开销（作用域/迭代） |
| + 每行 26B 文本 | 2.4 | 文本 push ≈ 0.1ns/B |
| + 每行 1 个整数写出 | 6.6 | 单次「路径求值 + 写出」≈ 43ns |
| + 每行 1 个字符串写出（含转义） | 6.6 | 与整数写出同价（转义已零分配） |
| + 每行 1 个条件块 | 9.0 | 条件求值 + 分支 ≈ 70ns/行 |

### 优化历程（T010 期间，同一夹具）

| 阶段 | 吞吐（ops/sec） | 关键改动 |
|------|---------------:|---------|
| 首测 | 1,896 | 模型深拷贝 + 逐字符转义（基线） |
| 第一轮 | 19,816 | `Rc` 共享 List/Object；文本化零中间分配；转义按字节段批量复制；错误路径懒构造 |
| 第二轮 | 28,241 | `Value::Str` → `Rc<str>`；`Literal::Str` → `Rc<str>`；输出缓冲预分配 |
| 第三轮 | 30,579 | 转义 8 字节 SWAR 快路径；LTO + 单代码元；热路径内联；二段路径直取；`Box<RenderError>` |
| F014 原生编译 | 69,257 | 字面量池（`Rc<str>` 预建）+ 路径单语句组合（零中间克隆）+ 属性访问每站点内联缓存（模板 → Rust → cdylib） |

## 结论

1. **F014 原生编译达到并超过目标**：p50 13.7µs（优于 C# 15.0µs）、吞吐 69,257/s（**2.07x C#**）、
   p99 31µs（C# 160µs），且 8 用例 + 基准夹具逐字节一致（`RAZOR NATIVE PASSED`）。
2. **解释器保留为回退路径**：31.3k/s 吞吐与 C# 同档（0.94x），无 GC 长尾、数字稳定；
   用于无 Rust 工具链环境与模板热改场景。
3. **架构结论**：解释器结构极限（单次「求值+写出」≈ 30ns）决定了无法在 p50 域胜出 JIT；
   F014 生成代码（字面量池 + 路径单语句组合 + 每站点内联缓存）将单行成本压到 ≈ 140ns，
   是达到/超过 C# 的决定性路径。本目录三引擎表即基准基线。
4. 复现（三引擎）：`powershell -ExecutionPolicy Bypass -File scripts\bench_view.ps1 [-Iterations N] [-SkipBuild]`；
   8 用例原生校验：`scripts\razor_native.ps1`。
