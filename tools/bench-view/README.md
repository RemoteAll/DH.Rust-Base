# bench-view：Razor 视图渲染性能基准（Rust 引擎 vs C# 原生 Razor）

目的：验证「Razor 子集模板引擎」（方案 C）的性能目标——小页面（≤300 节点、100 行数据）
单线程 warm 渲染吞吐不低于 C# 原生 Razor（同口径），并为 F012（性能基准）验收提供实测数据。

## 对比对象

| 侧 | 实现 | 运行方式 |
|----|------|---------|
| Rust | `dhrust::razor`（本仓库；解释器：解析一次 + 逐节点求值/写出） | `bench-view`（本目录，Release：LTO + 单代码元） |
| C# | RazorEngineCore 2026.1.1（原生 Razor 编译为委托，关闭调试信息） | `tools/csharp/RazorInterop bench`（Release，net10.0） |

两端同口径：模板解析/编译**只做一次**；计时循环内仅执行「模型绑定 + 渲染」；
warmup 默认 1000 次、计时 20000 次；每次迭代单独取时间戳并计算分位。
模型为同一 JSON（`fixtures/data.json`，100 行 × 4 字段）；模板 `fixtures/template.cshtml`
（表格循环 + 条件属性 + 成年判断，输出约 7.5KB）。

基准前先做 sanity：双端渲染同一夹具并**逐字节比对**，不一致直接失败（防止拿"渲染不同内容"比速度）。

## 测试环境

- Windows 11（本机）；rustc 1.98.1，Release（仓库根与 bench-view 均启用 `lto = true`、`codegen-units = 1`）；
- .NET 10 Release；两端均为单线程、进程内循环；
- 公平性说明：两端均使用各自发布默认设置，无 unsafe 预缓存、无跳过转义等基准技巧。

## 实测结果（2026-09-28）

### 主场景（100 行循环，20000 次迭代）

| 指标 | Rust | C# |
|------|-----:|----:|
| 吞吐（ops/sec） | **30,579** | 33,057 |
| 均值（µs） | 32.59 | 29.18 |
| p50（µs） | **31.00** | 15.60 |
| p90（µs） | **33.30** | 87.20 |
| p99（µs） | **64.20** | 159.30 |

> 复跑波动：吞吐比在 0.83x ~ 1.24x 之间摆动，取决于 C# 端 GC 命中时机；
> Rust 侧 p50≈p90（无长尾），数字稳定可复现。

### 性能分解（探针模板，p50/次）

| 微型模板（均 ×100 行） | p50（µs） | 说明 |
|----------------------|----------:|------|
| `foreach` 空循环 | 2.0 | 循环框架开销（作用域/迭代） |
| + 每行 26B 文本 | 2.4 | 文本 push ≈ 0.1ns/B |
| + 每行 1 个整数写出 | 6.6 | 单次「路径求值 + 写出」≈ 43ns |
| + 每行 1 个字符串写出（含转义） | 6.6 | 与整数写出同价（转义已零分配） |
| + 每行 1 个条件块 | 9.0 | 条件求值 + 分支 ≈ 70ns/行 |

### 优化历程（T010 期间，同一夹具）

| 阶段 | 吞吐（ops/sec） | 关键改动 |
|------|---------------:|---------|
| 首测 | 1,896 | 模型深拷贝 + 逐字符转义（基线） |
| 第一轮 | 19,816 | `Rc` 共享 List/Object；文本化零中间分配；转义按字节段批量复制；错误路径懒构造 |
| 第二轮 | 28,241 | `Value::Str` → `Rc<str>`；`Literal::Str` → `Rc<str>`；输出缓冲预分配 |
| 第三轮 | 30,579 | 转义 8 字节 SWAR 快路径；LTO + 单代码元；热路径内联；二段路径直取；`Box<RenderError>` |

## 结论

1. **数字目标达标**：小页面单线程 warm 吞吐 **约 3.0 万次/秒**，三倍于「≥1 万次/秒」目标；
   尾延迟稳定（p99 ≈ 64µs，无分配尖峰），适合在线服务。
2. **同口径对比（F012）**：p50 域 C# 快约 2 倍（15.6µs vs 31.0µs）——属结构性差距：
   C# 侧是 JIT 编译出的模板本机方法，Rust 侧是树遍历解释器；但 C# 因 GC 存在
   87µs / 159µs 的 p90/p99 长尾，**吞吐（均值口径）与 Rust 同档（典型 0.93x）**。
3. **F014 评估结论**：当前解释器已接近结构极限（单次「求值+写出」≈ 30ns，整行 ≈ 310ns）；
   若要稳定超过 C# p50，需按 F014 将模板编译为 Rust 函数（Askama 级代码生成），
   预估可再获数倍提升；建议批次 4+ 按需实施。本目录可直接作为 F014 前后的对照基线。
4. 复现：`powershell -ExecutionPolicy Bypass -File scripts\bench_view.ps1 [-Iterations N] [-SkipBuild]`
